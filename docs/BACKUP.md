# 备份、恢复与代码回退

[← 返回项目首页](../README.md)

代码、战役数据和个人恢复码是不同的东西。Git 提交能回退代码；它不会替你保存 `data/`。个人恢复码能找回成员身份；它不是战役备份。

## 三模式版本升级

当前程序版本 `2.0.0-beta.1`，数据库结构版本 **2**。首次打开版本 1 数据库时，程序先用 SQLite 一致性备份保存原库与配套清单，再在事务内升级；失败不留下半张新表或半批角色。旧角色仍保留，房主确认后再注册到新席位。

本地 `before-three-modes-20261106` 标签保留本次升级前的代码检查点。正式数据已在本次开发前创建 `before-three-modes` 一致性备份；后续开发验收全部使用隔离数据，没有替你启动或迁移正在使用的正式房间。

需要回退到版本 1 时，不要只切换 Git 再直接打开版本 2 数据库。先停机并备份当前库，切换到配套代码，再按原库清单恢复对应版本 1 备份。版本 2 程序的备份恢复工具会拒绝不匹配的数据库结构，避免混用。

## 选择合适的备份

| 方式 | 适用情况 | 注意 |
| --- | --- | --- |
| 房主在「房间设置」导出冒险 JSON | 当前战役、角色、场景、图片、治理、回合与记录 | 恢复会替换当前冒险；先导出当前状态 |
| 停止主机后完整复制 `data/` | 新手保存整个本机数据目录 | 必须先等房主进程退出；不要运行时只复制 `game.sqlite` |
| `npm run backup` | 创建主机数据库的一致性备份 | 保留 `.sqlite` 与 `.sqlite.manifest.json` 配套文件 |

把备份放在项目目录之外，并保留多份有日期的副本。完整数据库包含成员、会话等身份相关信息，不能当作公开示例上传。

## 不使用命令行的完整备份

1. 通知玩家暂停操作。在房主启动窗口按 `Ctrl+C`，等待进程退出。
2. 将项目根目录下整个 `data/` 文件夹复制到其他位置，例如自己的备份磁盘，并记录备份日期与当时使用的程序版本。
3. 下次正常启动前，不要移动或删除正在使用的原目录。

SQLite 运行时可能同时使用 `game.sqlite`、`game.sqlite-wal` 和 `game.sqlite-shm`。停止进程并复制整个目录，比运行中只复制一个数据库文件更可靠。需要在线备份时，使用下一节的一致性备份工具。

## 使用一致性备份工具

完成「安装或修复环境」后，在仓库根打开 PowerShell，让当前会话使用项目私有 Node：

```powershell
$runtime = Get-Content .\runtime.json -Raw | ConvertFrom-Json
$nodeDir = Join-Path $PWD ('.tools\node-v' + $runtime.node.version + '-win-x64')
$env:PATH = $nodeDir + ';' + $env:PATH

# 默认保存到 data/backups/
npm run backup
```

工具会输出备份路径，并生成同名 `.manifest.json`。清单包含数据库结构版本、代码提交与 SHA256 等校验信息。备份文件与清单必须一起保留。

本次已用隔离世界实际演练：提交 `2642203` + schema `2` + 备份编号 `c218e9bc-0e1c-4df3-bba6-93bdb819972a`。恢复后角色状态、民主 / 房主否决治理和原会话完全一致。复验可运行 `node scripts/verify-rollback.mjs <Git检查点>`，证据存于忽略的 `work/rollback-proof-*/result.json`。

通过 Git 克隆运行时，清单可记录实际代码提交；通过 Download ZIP 解压、没有 Git 的环境会记录 `unversioned`。这种情况下，请同时保留当时下载的源码压缩包、程序版本和备份清单，方便配对恢复。

使用过 `-DataDir` 的房主，应在备份与恢复命令中显式指向同一目录：

```powershell
$env:JIGE_DATA_DIR = 'D:\JigeRPG-Data'
npm run backup
# 使用完毕后，仅移除当前 PowerShell 会话的这项设置
Remove-Item Env:JIGE_DATA_DIR
```

## 恢复数据库备份

1. 先备份当前数据，再关闭房主进程。
2. 核对备份清单，使用与其数据库结构及代码版本匹配的程序。不要把新代码直接配上任意旧数据库。
3. 将 `.sqlite` 和其 `.manifest.json` 放在一起。在已配置私有 Node 的 PowerShell 中运行：

```powershell
npm run restore -- 'D:\JigeRPG-Backups\你的备份.sqlite'
```

恢复工具检查配套清单、SHA256、数据库完整性和结构；替换前会备份现有数据。成功后重新启动主机，分享新的临时公网地址，成员使用自己的恢复码找回身份。

若采用整个 `data/` 目录副本恢复，也必须先停止主机；保留当前目录副本，再放回对应程序版本的数据。不要在主机运行时覆盖文件。

## 代码回退

源码使用本地 Git 小步提交。需要撤销某项修改时，先阅读提交内容，通常可用 `git revert` 创建反向提交。数据库结构变更涉及配套恢复时，应先停机、备份，再按同一检查点恢复代码与数据。

原始旧版代码保留在历史和本地 `baseline-original` 检查点中；当前发布不附带旧版页面或旧版构建脚本。旧版存档迁移只复制，原始 JSON 与迁移报告也应另外保存。

## 不要提交到公开仓库

根目录 [.gitignore](../.gitignore) 排除了运行数据、数据库、备份、日志、运行时、依赖和构建结果。提交前仍应检查暂存内容：不要加入个人恢复码、私人战役 JSON、真实战役截图或凭据文件。
