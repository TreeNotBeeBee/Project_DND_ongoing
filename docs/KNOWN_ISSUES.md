# 当前开发版的已知问题

[← 返回项目首页](../README.md) · [试跑指南](QUICK_START.md)

本次发布整理的是当前代码与文档，没有同时修复以下功能问题。它适合继续开发和使用虚构数据试跑；完整 SRD 自动化及新增自制卡能力仍未完成。

## 地图图片已保存，却没有显示

**状态：待修复。** GM 的场景设置已有本地图与 URL 入口，但 Pixi 默认纹理加载路径与当前 CSP 存在冲突。隔离浏览器验证发现：默认 Blob Worker 会被限制；关闭 Worker 后，data URL 的 fetch 路径仍会被限制。因此 JPEG 等图片可能保存成功，背景却一直为空。

日志中的 `Scene updated` 表示场景状态已提交；footer 显示 PixiJS 表示渲染器启动成功。这两项都不能证明背景图片已经加载。没有角色也不应影响背景显示。

当前可先用默认网格、墙、门与地形试跑。重复保存同一图片通常不能解决加载问题。SVG 兼容绘图路径也尚未显示场景背景图片。后续需补齐图片加载、预览、失败反馈与网格对齐，并对两种渲染方式分别验收。

## 表单报错与待处理操作

**状态：待修复。** 建卡、场景等表单的规则错误可能显示在弹窗后面；被拒绝的操作仍留在待处理队列，继续修改表单再保存时可能被旧操作阻止。

临时处理：

1. 先关闭当前弹窗，查看页面上方的错误和待处理栏。
2. 若明确显示「操作未生效」，确认这是服务器拒绝的规则错误后，可「放弃此操作」，再打开表单修改并提交。
3. 如果显示离线「待提交」或版本冲突「需要复核」，先检查连接和最新房间状态，再决定安全重试、重提或放弃。不要把未确认的网络请求当作确定失败。

刷新页面不一定清除待处理操作，因为队列保存在当前浏览器中。关闭提示也不等于处理队列。后续需在弹窗内显示对应错误，并允许对确定未生效的表单修改后重新提交。

## 头像还没有成为地图棋子

**状态：待实现。** 角色头像支持上传或 URL，当前会显示在角色卡、队伍等位置；Pixi 与 SVG 地图仍显示圆形和名字首字，没有使用头像图片。

目前头像属于角色数据，玩家成员本身没有独立的账号头像字段。使用角色头像作为棋子、头像裁剪和失败回退需要后续补齐；不能把已有上传入口视作地图头像已完成。

## 建卡引导与自制卡

**状态：待完善 / 待规划。** 当前建卡以 SRD 职业、物种、背景和来源校验为基准。自定义名字、故事与外观已有入口；新增自制职业、物种、任意数值卡及对应自动化仍待规划。

表单尚未把所有规则选择转化成易懂的新手引导。界面中已有类型或条目，不代表相关编辑能力、特殊动作与规则全部可用。请按图鉴状态、服务器验证结果和开发说明判断。

## 规则覆盖仍有缺口

当前 [覆盖矩阵](../reference/automation-coverage.json) 包含 2017 个目录条目，其中 662 个标为 `unsupported`。目录同时包含参考数据和规则记录；**662 是未支持条目数，不是 662 个已复现 bug**。已有通过的规则与联机测试，也不表示完整 SRD 已经实现。

剩余范围包括大量确定性法术、职业 / 子职业能力、物种特性、专长、魔法物品与怪物特殊能力，以及变形、召唤、仪式和长施法等复杂流程。地图仍缺完整照明、特殊感官、挤行、垂直距离及多场景；任意历史操作的精准撤销也未完成。

详见 [DEVELOPMENT_STATUS.md](../DEVELOPMENT_STATUS.md)。目前发布以明确展示这些边界为准，不把未实现的数值规则重新标作「主持人裁定」来掩盖缺口。

## 反馈时带什么

记录操作步骤、房主或玩家身份、启动窗口错误、页面显示的渲染模式，以及待处理栏或日志的相关文字。涉及私人战役时先使用虚构数据复现；不要公开数据库、恢复码或真实战役截图。
